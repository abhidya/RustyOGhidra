## 0. Goals and the core problem

The four pipeline goals (AGENTS.md, compile-fix-loop-design §0) apply
unchanged: G1 playable game, G2 no dead ends, G3 pushes as heartbeat,
G4 fast kill of dead ends.

The problem this workstream exists for, stated plainly:

> **Compile-only greens are inventory, not progress.** The driver's
> `compile_only` tier (queue oracle `type: "compile_only"`) passes build +
> import-whitelist gates only, lands in `research/decomp/port-units-staging/`
> with `verified: false`, and is never wired into the app. Nearly every unit
> ported to date is in this tier. Only a behavioral oracle converts a staged
> unit into something G1 can use.

Phase 0 (landed, `0b84c788`) measured what is convertible. Verified in-repo
from `research/decomp/data/oracle-registry.json` summary:

| bucket                | units | meaning                                                            |
|-----------------------|------:|--------------------------------------------------------------------|
| `differential_vs_ts`  |   133 | ≥1 exported fn has a port-grade TS citation → diffable against TS  |
| `state_diff`          |   319 | TS citations but no port-grade fn; a gap-family exists             |
| `citations_no_family` |    58 | citations, no family-ctor neighborhood                             |
| `trace_only`          |   886 | no TS citations at all — no in-repo reference exists               |

10,954 functions across 1,396 units; 1,007 units fully gap-aligned. The
~86% with no usable TS reference (`trace_only` + most of `state_diff`'s
weaker citations) can only ever be verified against recorded Dolphin traces
— that is Phase 4, **named here and explicitly unscoped** (§7).

This plan designs Phases 1–3: a generic differential harness (Phase 1,
hard-gated on reproducing the damage-core result), its rollout over the 133
`differential_vs_ts` units (Phase 2), and state-diff oracles for the 319
`state_diff` units (Phase 3).

## 1. World state — the existing oracle path, verified in-repo

Everything in this section was read from the working tree; the generic
design in §3 must remain buildable against it.

### 1.1 The proven per-unit harness (`research/decomp/poc/wasm-port-poc/harness.mjs`)

The only oracle-green unit, `damage-core`, was verified by a hand-written
Node harness. Its mechanics, because the generic harness must reproduce all
of them:

- **Wasm loading.** `WebAssembly.compile` on `unit_poc.wasm` (overridable via
  env `POC_WASM`); imports resolved from a shim object behind a `Proxy` that
  **throws on any unshimmed import** — unknown seams fail loud, not silent.
  SDK vector ops (`gnt4_PSVEC*`/`gnt4_PSQUAT*`) are JS shims doing
  single-precision math via `Math.fround` (typed-array trick), matching
  paired-single hardware. Shim call counts are tallied and printed.
- **Pointer signedness.** wasm i32 args arrive in JS signed; all arena
  addresses are ≥ `0x80000000`, so every pointer is `>>> 0`'d. (A proven
  trap, commented in the file.)
- **Arena.** `arena.json`, generated by `gen_arena.py` **from boot.dol only**
  — segments of byte-order-converted data written into linear memory at the
  original GameCube addresses. Endianness is converted at *generation* time
  (swap4 for u32/f32, swap2 for s16 tables, raw for byte tables, typed pokes
  for scalars). Rule stated in the generator: "Everything emitted is
  DOL-sourced — no hand-entered values." Runtime-struct pointers
  (`0x80433930…`) are resolved by *reading the arena*, not hardcoded.
- **Input generation.** Seeded `mulberry32(0x6f42)` PRNG; cases are drawn
  from the **oracle's real domain**, with domain constraints derived from ROM
  semantics and documented per constraint (hp ≤ maxHp because hp>maxHp makes
  the ROM index out of table bounds; same-team actors must share per-team
  state; non-borg defenders never carry borg-derived ctx flags). Corpus size
  is `argv[2]` — the driver invokes `node harness.mjs 20000` (verified in
  `damage-core/provenance.json`).
- **Case encoding.** `encodeActor`/`encodeCase` write a TS-domain case into
  GC-address memory: zero-fill the object region, then write each field at
  its `+0xNNN` offset with the right width/signedness; big-endian byte order
  is preserved where the ROM reads bytes (borgNumber hi/lo); bss live state
  (hp mirror, per-team energy/rank) is written at its real addresses.
  **This encoder is the seed of the RomActor codec (§3.3).**
- **Comparison + tolerance policy.** Three tiers per case:
  1. `wasm === oracle` (the f64 TS reference) → **exact match**;
  2. else `wasm === oracle32(case)` → **f32-rounding-explained**, where
     `oracle32` is a second reference mirroring the ROM's *exact* f32/f64 op
     structure (`fround` at every single-precision op, tables fround'ed
     because the DOL stores f32 bit patterns while `damageFormula.json`
     stores decimal-shortened doubles);
  3. else **UNEXPLAINED**, with up to 8 full case dumps printed.
  There is **no epsilon anywhere**. A diff is either exactly explained by
  documented f32 semantics or it is a failure. This is the tolerance policy
  the generic harness inherits (invariant I-6).
- **Result** (verified `damage-core/oracle.log`): 19,998/20,000 exact +
  2 f32-rounding-explained + **0 unexplained** on `zz_003cd5c_`; 232/232 on
  `zz_0066298_` (exhaustive borg space); 4,000/4,000 on `zz_003d344_`
  (including the lethal flag and byte-level post-state); 2,000/2,000 on
  `FUN_80031634` through the SDK shim seam (bool + out-vector bytes).

**Latent trap, recorded as F-2:** `harness.mjs` never sets
`process.exitCode`. It reports failures only as printed counts.

### 1.2 The driver's oracle gate (`src/port_wasm_units.py`, verified)

- A unit's oracle spec comes from **the queue file**
  (`research/decomp/generated/finish-game-port/wasm-units.json`), field
  `unit["oracle"]`: `{command, cwd, env?, success_patterns?}` or
  `{type: "compile_only"}`. Every auto-generated chunk unit today is
  `compile_only`.
- `_run_oracle` executes `oracle["command"]` (rewriting `node` to the
  resolved node exe) in `repo_root/oracle["cwd"]`, env overlay with `{wasm}`
  substituted by the built wasm path, timeout `ORACLE_TIMEOUT_SECONDS =
  1800`. **Pass = exit code 0 AND every `success_patterns` regex matches the
  combined log.** Summary = first four `\d+/\d+` matches in stdout.
- On pass: artifacts (`unit.c`, `gnt4_shim.h`, `unit.wasm`, `oracle.log`) +
  `provenance.json` (`verified: true`, `tier: "oracle_green"`, oracle
  command/cwd/summary embedded) are committed to
  `research/decomp/port-units/<name>` with message
  `port: <name> wasm unit green (oracle <summary>)`. On fail: red verdict
  `oracle red: <summary>`, stage `oracle`, retryable.
- The driver already supports injectable `oracle_runner` (constructor param)
  — the gate itself needs **no redesign**, only per-unit specs (§3.4).
- Ordering: `product_priority` sidecar
  (`research/decomp/data/unit-priority.json`, [CF-2.14]) leads the serve
  key; it is computed *from the oracle registry*. Verified verdicts and the
  priority ordering are already coupled: registry → priority → driver.

### 1.3 The TS reference layer (`packages/combat/src/`)

- `rom/actor.ts` defines `interface RomActor` — the 1:1 actor-struct port.
  **Every field's doc comment carries its ROM offset in `+0xNNN` form**
  ("Fields keep their `+0xNNN` offsets in comments"), with chunk-file
  citations. `rom/` also holds `physics.ts`, `dispatch.ts`, `stream-vm.ts`,
  `state-tables.ts`, and 210 KB of selfchecks; `bridge.ts` composes
  RomActor with the generic `@gf/combat` runtime.
- Registry port-grade citations (202 functions) point into this tree; these
  are the reference implementations the 133 `differential_vs_ts` units diff
  against.
- The PoC's f64 oracle was produced by esbuild-bundling the TS reference
  (`sourceDamage.ts` → `oracle.mjs`); the same bundling path serves the
  generic harness.

## 2. Design principle

One principle governs every decision below, inherited from the pipeline:

> **Only the oracle decides green, and an oracle may only pass for reasons
> that are individually accounted for.** Every non-exact match must be
> *explained* (f32-rounding with an op-faithful witness) or it is a failure.
> Every input byte the wasm reads must have been *deliberately written* or
> the run is invalid. Nothing passes by coincidence of zeros.

## 3. The five settled decisions

These were left open by the workstream discussion; each is settled here with
its alternatives and the reasons they lost.

### 3.1 D-1: The generic harness is Node `.mjs`, living in `research/decomp/oracle-harness/` (GotYaForce repo)

**Decision.** The generic differential harness is JavaScript (`.mjs`), run
by `node`, in a new tracked directory `research/decomp/oracle-harness/` in
the product repo — a sibling of `poc/wasm-port-poc/`, not inside it (the PoC
directory stays frozen as the reference implementation the Phase 1 gate is
measured against). Its *generators* — arena generation, codec field-map
extraction — are Python, in the same directory, following the
`gen_arena.py` lineage.

**The owner rule and why it does not bind here.** The standing rule is
"port-stack tooling is Python-only" (the PS monitor incident). That rule
governs *orchestration tooling* — the driver, supervisors, queue tools in
OGhidra/rig. The oracle harness is not orchestration: it is **product-side
test code in the GotYaForce repo**, in the same category as the existing
`harness.mjs` the driver already invokes via `node` today (verified §1.2 —
`_run_oracle` special-cases `command[0] == "node"`). The rule's intent —
one language for the stack that operates the machine — is preserved: the
driver remains Python and merely *runs* the harness as a black-box command,
exactly as it runs the PoC harness now.

**Why not Python for the harness itself.** Three independent reasons, any
one sufficient:

1. **The reference IS JavaScript.** The f64 oracle is the esbuild-bundled TS
   port; the f32 classifier depends on `Math.fround` semantics at every op.
   A Python harness would still have to *execute JS* to obtain oracle
   values, so Python buys a second runtime (wasmtime) plus an IPC boundary
   while removing nothing.
2. **Float-semantics fidelity.** The entire tolerance policy (§1.1) rests on
   bit-exact reproduction of JS number semantics (f64 doubles with
   explicit `fround`). Reimplementing that in Python (`numpy.float32`
   round-tripping) is a new class of oracle bug in the one place oracle
   bugs are unfalsifiable.
3. **Proven path.** The 19,998/20,000 result was produced by this exact
   stack. Phase 1's gate is "reproduce that number through the generic
   path"; changing the runtime under the gate would make a gate failure
   ambiguous between generalization bugs and runtime-semantics drift.

**Rejected alternatives.** (a) Python-in-OGhidra: loses on all three counts
above, and puts product-repo test data behind a second repo boundary.
(b) Extending `poc/wasm-port-poc/` in place: entangles the frozen Phase 1
measuring stick with the thing being measured; the PoC dir also carries
model-run archives and one-off probes that must not become load-bearing.

### 3.2 D-2: Result artifact — `research/decomp/data/oracle-results/<unit>.json`

**Decision.** The harness writes one machine-readable verdict file per unit
run to `research/decomp/data/oracle-results/<unit>.json` (tracked). The
existing human-readable `oracle.log` stays exactly as-is (the driver copies
it into the artifact dir; provenance embeds the summary — unchanged).

**Why this path.** `research/decomp/generated/finish-game-port/` is
**driver-owned and wholesale-gitignored** — off-limits by instruction and
useless for durable artifacts (a `!file` negation cannot rescue a path whose
parent is excluded — the exact reason `unit-priority.json` lives in
`data/`, verified in `build_unit_priority.py`'s location note). The tracked
`research/decomp/data/` dir is the established sidecar home [CF-2.14]: the
driver already reads two files there (`unit-priority.json`,
`assembly-gate.json`), so a later driver change that *consumes* verdicts
(e.g. surfacing them on the dashboard, or feeding priority regeneration)
crosses no new boundary.

**Schema** (`result_schema: 1`; unknown fields tolerated, missing required
fields = malformed = fail):

```json
{
  "result_schema": 1,
  "unit": "damage-core",
  "generated_at": "<iso8601 utc>",
  "harness": {"entry": "research/decomp/oracle-harness/run-unit.mjs",
               "git_rev": "<GotYaForce HEAD at run time>"},
  "wasm": {"path": "<as invoked>", "sha256": "<hex>"},
  "corpus": {"seed": "0x6f42", "n": 20000},
  "spec_sha256": "<hex of the unit oracle-spec file, §3.4>",
  "functions": [
    {"name": "zz_003cd5c_", "cases": 20000, "exact": 19998,
     "rounding_explained": 2, "unexplained": 0, "verdict": "pass"},
    {"name": "zz_0066298_", "cases": 232, "exact": 232,
     "rounding_explained": 0, "unexplained": 0, "verdict": "pass"}
  ],
  "coverage": {"offsets_written": 41, "offsets_read_unwritten": 0,
                "sentinel_reads_detected": false},
  "unexplained_cases": [],
  "verdict": "pass"
}
```

Rules: `verdict` is `"pass"` iff every function verdict is `"pass"`;
a function passes iff `unexplained == 0` **and** the rounding-explained
bound holds (§5 F-5) **and** coverage is clean (§3.3). `unexplained_cases`
carries up to 8 full replayable case dumps (the PoC's diff-dump behavior,
made machine-readable). The file is **overwritten per run** — history lives
in git, which is exactly where the driver's commit-per-green already puts
verdict evolution.

**Exit-code contract** (closes F-2): the harness process exits 0 iff
`verdict == "pass"` and the result file was written; any exception,
malformed spec, or coverage violation exits nonzero. The driver-side spec
additionally carries `success_patterns` (§3.4) as a belt-and-braces second
factor, so a future harness bug that "forgets" to fail the exit code still
cannot green a unit alone.

### 3.3 D-3: RomActor codec — TS → arena bytes, field map extracted from `actor.ts`, gaps loud

**Direction.** The codec encodes **TS-domain values into GC-address arena
bytes** (TS → memory), same direction as the PoC's `encodeActor`. The wasm
side is the system under test; it must read the same struct layout the ROM
reads, so the canonical representation is ROM memory and the TS reference
consumes the *same case object* natively. Decoding (memory → TS) is
implemented only for **post-state assertion** of written-back fields (the
PoC's `zz_003d344_` check reads hp/prevHp back out) — never for input
generation.

**Field map derivation — single source of truth.** `rom/actor.ts` already
encodes the complete field↔offset mapping as `+0xNNN` doc comments with
chunk citations (§1.3, verified). The map is **extracted, not
hand-written**: a Python generator
(`research/decomp/oracle-harness/gen_actor_field_map.py`) parses
`actor.ts`'s JSDoc offset annotations and emits
`research/decomp/oracle-harness/actor-field-map.json` — one record per
field: `{tsField, offset, width, kind (u8/s8/u16/s16/u32/s32/f32/vec3/
bytes/port_side), note}`. Width/kind comes from a small annotation grammar
in the comments where the offset alone is ambiguous; fields the extractor
cannot fully type are emitted with `"kind": "unmapped"` — present, visible,
and unusable (below). Regeneration is deterministic; the JSON is tracked,
so `actor.ts` drift shows up as a reviewable diff. Fields marked port-side
(no ROM offset, e.g. `physicsRuntime`, `hasBCharge`) are emitted as
`port_side` and are never encoded.

**Why extraction beats a hand-maintained table.** The 2026-08-20 migration
incident [CF-2.9] is the standing proof that parallel hand-maintained
copies of one truth diverge silently. `actor.ts` is reviewed product code
with per-field citations; a second hand-written offset table would be a
second, uncited truth.

**Coverage gaps made LOUD — three independent mechanisms:**

1. **Sentinel-poisoned arena.** Before encoding a case, every scratch
   object region is filled with `0xA5`, **not zeroed**. The PoC zero-fills;
   zeroes are the single most likely "accidentally correct" value (null
   pointers, zero flags, zero floats), so a field the codec failed to write
   that the wasm reads would frequently agree with a TS reference that also
   defaulted to zero — a silent false pass. With poisoning, an unencoded
   read yields `0xA5A5A5A5`-derived garbage and diverges immediately.
   (DOL-sourced arena segments are never poisoned — they are real data.)
2. **Write-set vs read-set audit.** The codec records every offset it wrote
   per case. The unit's oracle spec declares the read-set (`reads`: offsets
   /ranges per exported fn — authored once per unit from the verbatim C,
   which the spec author must consult anyway to build the case domain). Any
   declared-read offset not in the write-set fails the run *before* any
   case executes (`coverage.offsets_read_unwritten > 0` → nonzero exit).
   Sentinel poisoning backstops read-set declarations that are incomplete.
3. **`unmapped` is a refusal, not a default.** If a unit's spec references a
   TS field whose map record is `unmapped` or missing, the harness exits
   nonzero with verdict `"blocked_codec"` naming the field. The fix is a
   commit to `actor.ts` annotations or the extractor — never an inline
   zero.

Non-RomActor structs (descriptor pages, bss globals, records like the PoC's
`REC`) get per-unit encoders in the unit spec using the same primitives and
the same three mechanisms; the RomActor codec is the shared core because the
gap-aligned units overwhelmingly take actor pointers.

### 3.4 D-4: Wiring per-unit oracle commands into the driver — the oracle-spec sidecar

**Decision.** Per-unit oracle commands live in a tracked sidecar,
`research/decomp/data/oracle-commands.json`, mirroring the
`product_priority` sidecar pattern exactly [CF-2.14]:

```json
{
  "generated_by": "research/decomp/oracle-harness/ (hand-authored specs, validated)",
  "spec_schema": 1,
  "units": {
    "auto-c0012-004": {
      "exports_sha256": "<sha256 of the unit's sorted exported_functions>",
      "oracle": {
        "command": ["node", "run-unit.mjs", "--unit", "auto-c0012-004", "--n", "20000"],
        "cwd": "research/decomp/oracle-harness",
        "env": {"ORACLE_WASM": "{wasm}"},
        "success_patterns": ["UNEXPLAINED\\s*:\\s*0", "\"verdict\": \"pass\""]
      }
    }
  }
}
```

The driver, at queue load, overlays `unit["oracle"]` with the sidecar entry
**iff** the entry's `exports_sha256` matches the queue unit's current export
set. Absent file, absent entry, or hash mismatch ⇒ the unit keeps its queue
spec (`compile_only`) — bit-identical current behavior, the same absent-file
semantics as the priority sidecar. A hash mismatch additionally emits a
journal event (`oracle_spec_stale`) so drift is visible, not silent.

**Why this and not the alternatives.**

- *Editing the queue file*: `wasm-units.json` is generated, gitignored, and
  regenerated wholesale — hand edits are erased by the next Tier-0 run, and
  the file is driver-owned. Off-limits by both instruction and design.
- *Teaching the queue generator to embed specs*: couples oracle authoring to
  queue regeneration (a heavyweight, driver-paused operation) and puts
  tracked content's source of truth inside an untracked pipeline. The
  sidecar keeps oracle rollout independently deployable: add an entry,
  the *next* attempt at that unit runs oracled. No driver state file is
  read or written by any part of this.
- *Per-unit files consumed directly by the harness, driver unaware*: the
  driver's gate (§1.2) is already exactly the right shape — command + cwd +
  env + success patterns + verdict recording + commit-per-green. Bypassing
  it would mean re-verified units whose green never reaches the state
  machine, the journal, or the priority loop.

**Driver delta (small, T-phase §6):** one overlay function reading the
sidecar (a sibling of `_unit_priority`), called where `_process_unit` reads
`unit.get("oracle")`. No state-file schema change: `tier` already
distinguishes `compile_only` from `oracle_green`.

**Already-settled staged units.** The 133 `differential_vs_ts` units that
are *already* green at `compile_only` tier are settled — the queue loop will
not revisit them. Promotion is a **re-verification pass**, not a hand edit:
a sanctioned CLI subcommand (design: `reverify-unit --unit <name>`, sibling
of `settle-unit`, same driver lock) rebuilds nothing, runs the sidecar
oracle against the *committed* staged `unit.wasm`, and on pass emits the
journal checkpoint + verdict event, updates the record's tier to
`oracle_green`, moves the artifact from `port-units-staging/` to
`port-units/`, and commits — all through the journal [CF-2.9]. Hand-editing
`wasm-units-state.json` remains forbidden; the 2026-08-20 migration is the
standing proof of why.

### 3.5 D-5: Phase acceptance gates (each a number — §6 table)

Settled as measurable gates, one per phase, in §6. Phase 1's is the
hard gate the workstream is anchored on: **the generic path must reproduce
the damage-core result before any second unit gets a spec.**

## 4. Invariants

- **I-1 (oracle decides green).** No mechanism in this workstream may mark a
  unit verified except a driver-gate (or `reverify-unit`) run of its oracle
  command ending pass. Unchanged from the pipeline; restated because the
  result-artifact file (§3.2) could tempt a reader to treat its presence as
  a verdict. It is evidence, not a verdict.
- **I-2 (determinism).** Given (wasm sha256, spec sha256, harness rev, seed,
  N), a harness run is bit-reproducible: same verdict, same counts, same
  result JSON modulo `generated_at`. All randomness flows from the seeded
  PRNG (`mulberry32` lineage); the seed is in the spec and echoed in the
  result.
- **I-3 (DOL-sourced arena).** Arena content comes from `boot.dol` (or other
  shipped game data) via generators; no hand-entered memory values, ever.
  Byte-order conversion happens at generation time (the `gen_arena.py`
  rule). Scratch regions are the only harness-authored memory, and they are
  sentinel-poisoned (§3.3).
- **I-4 (loud gaps).** No input byte the unit reads may be an accident:
  sentinel poisoning + write/read-set audit + `unmapped`-refusal (§3.3).
  Zero-fill of scratch regions is forbidden in the generic harness.
- **I-5 (exit-code + pattern double gate).** A unit passes only if the
  harness exits 0 **and** every `success_patterns` regex matches. Specs MUST
  include at least the two patterns shown in §3.4 — a pattern that pins
  `UNEXPLAINED: 0` and one that pins the machine verdict.
- **I-6 (no epsilon).** The only permitted non-exact agreement is
  f32-rounding-explained, defined as `wasm === oracle32(case)` where
  `oracle32` mirrors the ROM's op-level float structure. No relative/absolute
  tolerance, no ULP windows, no percentage thresholds on correctness.
- **I-7 (frozen measuring stick).** `poc/wasm-port-poc/` is not modified by
  this workstream. Phase 1 is measured as agreement with its committed
  output (`port-units/damage-core/oracle.log`), which only means something
  if the stick doesn't move.
- **I-8 (sidecar, never state).** All new persistent data lives in tracked
  sidecars under `research/decomp/data/` or in
  `research/decomp/oracle-harness/`. Nothing under
  `generated/finish-game-port/` is read as truth or written at all. Verdict
  changes go through journal-emitting code paths only [CF-2.9].
- **I-9 (spec pinned to exports).** Every sidecar entry carries
  `exports_sha256`; a queue regeneration that changes a unit's export set
  silently *disables* that unit's oracle (falls back to `compile_only`) and
  loudly journals it — it can never run a stale spec against a different
  function set.
- **I-10 (reference independence is documented, not assumed).** Each unit
  spec names its TS reference file(s) and the registry citation grade it
  relied on. Where the TS port was itself derived by reading the same
  decompiled C (most of `rom/`), the oracle proves *agreement with the
  reviewed TS port*, not ground truth — the spec must say so
  (`reference_kind: "ts_port"` vs `"behavior_trace"`), because Phase 4 is
  the only tier that upgrades this.

## 5. Failure-mode analysis

- **F-1: Silent-zero agreement (both sides read a default).** The classic
  differential-testing false pass: codec forgets a field, wasm reads 0, TS
  reference also defaults 0, corpus passes. Killed three ways by I-4. The
  residual risk — TS reference *and* sentinel-garbage wasm agreeing — is
  negligible for value-bearing fields and caught by the read-set audit for
  flag fields.
- **F-2: Harness exits 0 on failure.** Present in `harness.mjs` today
  (§1.1); it never sets `process.exitCode`, so under the driver's gate a
  fully-diffing run would pass unless `success_patterns` were authored.
  The generic harness closes this structurally (§3.2 exit contract), and
  I-5 makes the pattern half mandatory so neither factor is a single point
  of failure. This finding is also why Phase 1's gate includes a
  **deliberate-red rehearsal** (§6): flip one arena byte, assert the
  driver records `oracle red`.
- **F-3: Echo-chamber oracle.** The TS reference was written by humans
  reading the same Ghidra export the wasm unit was extracted from; a shared
  misreading passes. Mitigations: I-10 labeling; unexplained-case dumps are
  replayable so human triage compares against the verbatim C, not the TS;
  registry citation *grade* (only `port`-grade fns qualify for
  differential specs); and the Phase 4 boundary is explicit — differential
  green means "agrees with the reviewed port," which is the honest maximum
  claim without traces.
- **F-4: Seed overfitting / domain gerrymandering.** A spec author can make
  any unit pass by shrinking the input domain until the disagreeing region
  is excluded. Mitigations: domain constraints must each carry a
  ROM-semantics justification comment (the PoC's discipline, §1.1, made a
  spec-review requirement); corpus N is part of the gate (§6) and the spec
  is committed and diffable; and the rounding-explained bound (F-5) stops
  the other lever.
- **F-5: `rounding_explained` becomes a dumping ground.** The tier exists
  for genuine f32-vs-f64 divergence (damage-core: 2 in 20,000). Bound: a
  function's verdict is `pass` only if `rounding_explained / cases ≤ 0.1%`
  **and** every such case satisfies the `oracle32` equality (I-6). A unit
  genuinely exceeding the bound is a spec/oracle32 design question for a
  human, surfaced as `verdict: "fail_rounding_bound"` — never auto-passed.
- **F-6: Spec/queue drift.** Queue regeneration renames units or reshuffles
  export sets. I-9's `exports_sha256` pin + journaled fallback makes this
  fail safe (unit degrades to compile_only visibly) rather than fail wrong
  (stale spec runs against the wrong functions).
- **F-7: Timeout starvation.** `ORACLE_TIMEOUT_SECONDS = 1800`. The PoC runs
  26,232 cases in seconds; but state-diff oracles (Phase 3) step frame
  loops. Specs carry `--n`; the Phase 3 pilot (§6) must measure wall time
  and either fit N inside ~25 minutes with headroom or split per-function
  commands. No spec may rely on raising the driver timeout (schema-capped
  config changes crash the driver at startup — a known trap class).
- **F-8: Concurrent mutation.** `reverify-unit` takes the driver lock (as
  `settle-unit` does) and refuses while a driver is alive — `WinError 5`
  races and lost updates are proven failure modes on this machine.
- **F-9: Registry staleness.** The registry is a Phase-0 *snapshot*; TS
  citations move as `packages/` evolves. The spec, not the registry, is
  authoritative at run time (it names actual files); the registry is the
  *discovery* index. Regeneration cadence: rebuild registry + priority
  sidecar after each phase gate (it is deterministic and cheap).
- **F-10: Node resolution drift.** The driver resolves `node` via env →
  PATH → rig runtime checkout (§1.2). Harness specs always use bare
  `"node"` and let the driver resolve — a spec hardcoding a node path
  would break under the rig's runtime relocation.

## 6. Phases and acceptance gates

Every gate is a number; a phase without its number is not done, and no
phase starts before its predecessor's gate is green.

**Phase 0 — Oracle registry. DONE** (`0b84c788`). Gate was: registry built
deterministically over all 10,954 queue functions with bucket counts
published. Verified: 133 / 319 / 58 / 886, 1,007 fully gap-aligned units.

**Phase 1 — Generic harness + RomActor codec, hard-gated on damage-core.**
Build `oracle-harness/` (runner, codec, field-map extractor, arena
generalization) and a `damage-core` unit spec, then reproduce the committed
result **through the generic path** — the PoC harness untouched (I-7).

*Gate (all seven, exact):*
1. `zz_003cd5c_`: ≥ 19,998/20,000 exact, ≤ 2 rounding-explained,
   **0 unexplained** at seed `0x6f42`, N=20,000;
2. `zz_0066298_`: 232/232 exact (exhaustive);
3. `zz_003d344_`: 4,000/4,000 exact incl. lethal flag + post-state bytes;
4. `FUN_80031634`: 2,000/2,000 exact through the SDK shim seam;
5. coverage clean: `offsets_read_unwritten == 0`, zero sentinel-reads;
6. deliberate-red rehearsal: one flipped arena byte produces nonzero exit,
   `verdict: "fail"`, and (in a driver dry-run) an `oracle red` record;
7. determinism: two consecutive runs byte-identical result JSON
   (modulo `generated_at`).

**Phase 2 — Differential rollout over the 133 `differential_vs_ts` units.**
Author specs in priority-sidecar order; land the driver overlay +
`reverify-unit` (the only driver code in the workstream); promote settled
staged units through re-verification.

*Gate:* **≥ 100 of 133** units carry a terminal differential verdict —
`pass` (promoted to `oracle_green`) or a diagnosed `fail` with replayable
`unexplained_cases` committed — with per-fn corpus **N ≥ 10,000** for
class-A/B functions (exhaustive where the domain is smaller), and **zero**
units passed with any unexplained case. The remaining ≤ 33 must each have a
recorded blocker (`blocked_codec`, `fail_rounding_bound`, or a named spec
gap) — none merely unattempted.

**Phase 3 — State-diff oracles for the 319 `state_diff` units.** These have
TS citations but no port-grade single function: the oracle compares
**post-state snapshots** (actor structs + named bss) after driving both
sides through the same scripted sequence, using the §3.3 decode direction
for read-back. Pilot first (F-7): 5 units chosen from gap-partial families,
measuring wall-time and codec pressure; the pilot report sets Phase 3's
corpus floor.

*Gate:* pilot: **5/5** units reach terminal verdicts within the 1800 s
driver timeout; rollout: **≥ 75** of 319 units with terminal state-diff
verdicts under the pilot-set corpus floor, zero unexplained on any pass.
(75 is deliberately conservative: state-diff spec authoring is the
bottleneck and the bucket's citation quality is heterogeneous; the gate is
revisited upward, never downward, after the first 75.)

**Phase 4 — Dolphin trace-recorded oracles (the ~86% with no TS
reference). NAMED, EXPLICITLY UNSCOPED.** Recording register/memory traces
in Dolphin at function boundaries and replaying them as oracle corpora is
the only route to verified verdicts for the 886 `trace_only` units (and the
upgrade path out of F-3 for everything else). Nothing in this document
designs it; Phases 1–3 must not embed assumptions that foreclose it —
concretely, the result schema's `reference_kind` field (I-10) and the
spec's command shape are already trace-compatible.

## 7. Out of scope

- Phase 4 design (above).
- Any harness/codec/driver *implementation* — this is the design doc those
  changes will cite.
- Browser-side verification (the PoC's `browser-expectations.json` path)
  — unchanged and untouched.
- Assembly-gate interaction beyond what exists: promoted units simply enter
  the same rolling link the gate already sweeps.
- Model/LLM involvement: this workstream contains **zero** LLM calls. It is
  deterministic tooling end to end.

## 8. Goals traceability

| Goal | Mechanism here |
|------|----------------|
| G1 playable game | Verified units are the only units the app may integrate; Phases 1–3 convert 133 + 319 units of staged inventory into integrable code, in product-priority order (§1.2, §6). |
| G2 no dead ends | Hard Phase 1 gate before any rollout spend; terminal-verdict accounting in Phase 2/3 gates (a unit may fail, but not linger); F-4/F-5 bounds stop unfalsifiable "almost passing" grinding. |
| G3 pushes as heartbeat | Every promotion is a driver/`reverify-unit` commit+push through the existing gate; verdict artifacts are tracked files whose changes ride the same pushes. |
| G4 kill dead ends fast | Loud-gap refusals (I-4), journaled spec-drift fallback (I-9), deliberate-red rehearsal (§6.1.6) prove the failure path before it is needed. |

## 9. Falsifiers

This design is wrong, and must be revised rather than defended, if:

1. Phase 1 cannot reach its seven-part gate within a bounded effort while
   the PoC harness still reproduces its numbers — that would mean the
   "generic" abstraction is the wrong cut, not that the gate is too strict.
2. More than a handful of Phase 2 specs need per-unit *harness* code (not
   spec data) — the spec schema is then under-expressive and the
   harness/spec boundary must move.
3. The `0.1%` rounding bound (F-5) rejects a unit whose divergence is
   genuinely and provably f32-structural — the bound then needs a
   per-unit, human-approved override field, not silent loosening.
4. Sentinel poisoning (I-4) produces false *failures* at meaningful rates
   (wasm legitimately reading uninitialized ROM memory the real game also
   reads) — then the arena needs those regions DOL-sourced, and the
   incident is evidence the read-set audit found real under-declaration.
5. Phase 3's pilot shows the 1800 s timeout cannot hold any honest
   state-diff corpus — then the per-function command split (F-7) is
   insufficient and the driver timeout policy itself needs an owner
   decision.
